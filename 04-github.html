¿Qué es GitHub?

03
Básico

Repositorios

Un repo en GitHub es la casa de tu proyecto. Lo creas en la web y luego conectas tu Git local a él.

conectar un repo local
# Creaste el repo vacío en github.com → conecta tu local
git remote add origin git@github.com:yo/proyecto.git
git branch -M main
git push -u origin main

# Clonar uno existente
git clone git@github.com:yo/proyecto.git
Visibilidad

Público = cualquiera puede leer. Privado = solo invitados. Ambos gratis.

04
Open source

Fork y clone

Un fork es tu copia personal del repo de otra persona. Lo cambias libremente y luego propones cambios de vuelta.

original
→ fork →
tu fork
→ clone →
tu PC
fork flow
# 1. Fork en la web (botón Fork) → crea yo/proyecto
# 2. Clona tu fork
git clone git@github.com:yo/proyecto.git
# 3. Añade el original como upstream
git remote add upstream git@github.com:original/proyecto.git
05
Recurso central

Pull Requests

Un PR es una propuesta: 'mezcla mi rama en main'. Muestra el diff, corre chequeos y junta revisiones antes de mergear.

rama feature
→ open PR →
revisión + CI
→ merge →
main

1. Abrir

Sube tu rama, pulsa 'Compare & pull request', escribe título y descripción claros.

2. Revisar

Compañeros comentan línea por línea. Piden cambios o aprueban.

3. Chequeos

Actions corren tests, linters, builds. Deben pasar para mergear.

4. Mergear

Merge, squash-merge o rebase-merge. Luego borra la rama.

06
Seguimiento

Issues

Las Issues rastrean bugs, tareas e ideas. Cada una tiene número, responsable, labels y PRs vinculados.

referenciar en commits
# Un commit puede cerrar un issue al mergear
git commit -m "fix: login crash. Closes #42"
#  Closes, Fixes, Resolves + #numero → cierra al merge
Tip

Plantillas de labels mantienen las issues ordenadas: bug, enhancement, good-first-issue, help-wanted.

08
CI/CD

GitHub Actions

Automatiza en eventos: push, PR, schedule, release. Defines jobs en YAML dentro de .github/workflows/.

.github/workflows/ci.yml
name: CI
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm ci
      - run: npm test
Por qué importa

Cada PR muestra checks verde/rojo. Ningún código roto llega a main.

09
Hosting

GitHub Pages

Publica un sitio estático gratis desde tu repo. Ideal para docs y demos.

dos formas
# Opción A: rama gh-pages con HTML/CSS/JS
git switch --orphan gh-pages
# Settings → Pages → Branch: gh-pages

# Opción B: genera con Actions (build de Vite/Next)
# Settings → Pages → Source: GitHub Actions
# → URL: https://usuario.github.io/repositorio/

CLI · instalar

Instalar gh — por sistema

La CLI oficial de GitHub te deja hacer todo desde el terminal. Elige tu sistema:

🪟 Windows
🍎 macOS
🐧 Linux
Windows
# Opción 1: winget (Windows 10/11)
winget install --id GitHub.cli

# Opción 2: Scoop
scoop install gh

# Opción 3: Chocolatey
choco install gh

# Verifica
gh --version
macOS
# Homebrew (lo más común)
brew install gh

# MacPorts
port install gh

# Verifica
gh --version
Linux
# Debian / Ubuntu (repo oficial)
curl -fsSL https://cli.github.com/packages/githubcli-archive-keyring.gpg \
  | sudo dd of=/usr/share/keyrings/githubcli-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" \
  | sudo tee /etc/apt/sources.list.d/github-cli.list > /dev/null
sudo apt update && sudo apt install gh

# Fedora / RHEL
sudo dnf install gh

# Arch
sudo pacman -S github-cli

# Verifica
gh --version
13
CLI · configurar

gh — autenticar

login
# Login interactivo (abre el navegador)
gh auth login
#  → elige GitHub.com → HTTPS o SSH → pega el token

# Comprueba el estado
gh auth status

# Renueva / cambia de cuenta
gh auth refresh

# Logout
gh auth logout
Tip

Tras el login, gh también configura las credenciales de git, así push funciona sin pedir contraseña.

CLI · pull requests

gh — Pull Requests

pr
# Crear PR con un comando
gh pr create --title "feat: login" --body "Añade login con Google"

# Listar PRs abiertos
gh pr list

# Ver el PR actual en el navegador
gh pr view --web

# Bajar el PR #42 a tu local
gh pr checkout 42

# Hacer review desde el terminal
gh pr review --approve --comment "Buen trabajo"

# Mergear (squash)
gh pr merge 42 --squash --delete-branch

18
Flujo completo

Un flujo de PR completo sin salir del terminal

el ciclo entero
# 1. Crea la rama
git switch -c feature/login

# 2. Trabaja y confirma
git commit -am "feat(auth): login"

# 3. Sube y abre el PR
git push -u origin feature/login
gh pr create --fill   # usa el último commit como base

# 4. Mira el CI
gh run watch

# 5. Mergear y limpiar
gh pr merge --squash --delete-branch

Pro tips

Configuración recomendada

git + gh config
# Editor y rama por defecto
git config --global init.defaultBranch main
git config --global pull.rebase true

# gh usa el editor de código
gh config set editor code --wait

# Plantilla de PR en el repo: .github/PULL_REQUEST_TEMPLATE.md
# Plantilla de issue: .github/ISSUE_TEMPLATE/*.md
Tip

Las plantillas de PR/issue rellenan la descripción, así cada PR sigue el formato de tu equipo.

Trampas

Errores comunes

🙈

Mergear sin CI verde

Siempre espera los checks. Un check rojo es un bug camino a main.

📝

PR sin descripción

Di qué cambió, por qué y cómo probarlo.

🗑️

Nunca borrar ramas

Las ramas muertas se acumulan. Borra tras mergear.
